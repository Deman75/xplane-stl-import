# Разработка и проверки

Приложение использует HTML, CSS и JavaScript без внешних зависимостей.
Открытие `index.html` через `file://` — основной способ запуска.

## Исходники

| Файл | Назначение |
| --- | --- |
| `web/core.js` | ASCII/binary STL, преобразование осей, срезы, наружные обводы, восстановление вырезов, OBJ8 |
| `web/plane.js` | Редактируемая геометрия, секции несущих поверхностей, AFL и экспорт ACF 1200 |
| `web/flight.js` | САХ, центровка, электромотор, винт и скрытые опоры |
| `web/app.js` | Интерфейс, Canvas-просмотрщик, Web Worker и готовность экспорта |
| `web/zip.js` | Создание ZIP в браузере |
| `web/bundled-assets.js` | Сгенерированная копия AFL и шаблона для запуска через `file://` |

Внутренние расчёты используют метры, X вправо, Y вверх, Z назад.
ACF использует собственные единицы; преобразования выполняет экспортер.
Форма тела и несущих поверхностей — приближение по срезам,
а не точное булево объединение STL. Аэродинамические поляры берутся из AFL.

## Основные тесты

Для разработки нужен Node.js 22 или новее. Установка пакетов не требуется:

```sh
npm test
```

Тесты используют встроенный `node:test`. Проверки на синтетической геометрии
работают без X-Plane. Проверки по файлам X-Plane и личной модели пропускаются,
если соответствующих файлов нет. Для дополнительных сравнений задайте
переменную `XPLANE_ROOT` с путём к установленному X-Plane.
STL, ACF и AFL пользователей не должны попадать в коммиты. Исключения —
подготовленный общий шаблон `input/PlaneMaker12_template.acf` и комплект `Airfoils/`.
После изменения встроенных файлов выполните `npm run build:assets` и закоммитьте
также обновлённый `web/bundled-assets.js`.

## Проверки браузера

Нужны Node.js 22+ и установленный Chrome. Его путь задаётся переменной
`STL_TEST_BROWSER` (на Windows по умолчанию используется обычный путь Chrome).

```sh
node tests/acf-readiness-smoke.cjs
node tests/viewer-live-smoke.cjs
```

Первая проверка генерирует временные STL и чистый тестовый ACF в `reports/`
и использует встроенные AFL; установленный X-Plane ей не нужен.
Вторая читает пользовательскую папку `STL_TEST_PROJECT` либо `input/Project333`.
`browser-smoke.cjs` — дополнительная проверка исходной архивной фикстуры
Project333; она требует именно прежние четыре STL и их контрольные размеры.
Эта личная фикстура не распространяется с репозиторием.

Браузер запускается скрыто с отдельным профилем в `reports/`; обычный профиль
Chrome не используется. Скриншоты и отчёты сохраняются там же и не коммитятся.
Браузерные проверки не заменяют открытие результата в Plane Maker и испытания
лётной модели в X-Plane.
